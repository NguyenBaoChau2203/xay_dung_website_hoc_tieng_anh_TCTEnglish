## Local operation and restart

Requires this checkout's existing Docker MariaDB10.5.23, local nonsecret launcher
metadata plus its saved local DB credential, and .NET SDK10 for file-based tools.
The web app still targets net9.0. Commands never start the web, speech, seeders,
workers or an AI provider. The importer never migrates, resets, deletes, updates
old content, creates accounts or rewrites learner history.

```powershell
pwsh -NoProfile -File scripts/start-local.ps1 -DatabaseOnly
pwsh -NoProfile -File scripts/writing-content.ps1 -Action baseline
pwsh -NoProfile -File scripts/writing-content.ps1 -Action validate -Level beginner
pwsh -NoProfile -File scripts/writing-content.ps1 -Action dry-run -Level beginner
pwsh -NoProfile -File scripts/writing-content.ps1 -Action pilot -Level beginner
pwsh -NoProfile -File scripts/writing-content.ps1 -Action import -Level beginner
pwsh -NoProfile -File scripts/writing-content.ps1 -Action import -Level beginner
pwsh -NoProfile -File scripts/writing-content.ps1 -Action export -Level beginner
pwsh -NoProfile -File scripts/shared-data.ps1 -Action Validate -DatabaseReady
pwsh -NoProfile -File scripts/shared-data.ps1 -Action Sync -DatabaseReady
pwsh -NoProfile -File scripts/shared-data.ps1 -Action Sync -DatabaseReady
pwsh -NoProfile -File scripts/writing-content.ps1 -Action verify -Level beginner
```

`baseline` is create-once. It captures18 public cells, all old Writing content,
and original row-hash multisets across all tables in ignored
`.appdata/local/writing-content-20261114/`. Never replace it after imports. The
private snapshot includes private Writing text/IDs and must remain ignored.
Runtime receipts/checkpoints are also ignored. Receipts bind stable keys to
local IDs and canonical content digests; they are not portable data packages.

`pilot` imports the first lesson in each format. `import` adds only missing
lessons in a single transaction under the canonical shared-data MariaDB lock.
Receipt data is staged before commit and atomically published afterward. If the
process stops between commit and receipt publication, the next run recovers
only a unique full-content match from this batch, never a baseline identity.
An existing receipt/content mismatch stops; there is no force overwrite mode.
`export` resumes completed roots without producing additional versions and stops
for a conflicting existing export. Keep unfinished canonical exporter files
intact and inspect them using the shared-data workflow rather than deleting them.

Later chats reuse this baseline, keys, importer and receipts. Fill their reserved
keys without renaming identities, update their own content file and run their
level explicitly. `verify` uses completed receipt items across batches; reserved
slots never count as imported. Run a new isolated disposable DB for each provider
roundtrip. `roundtrip` requires a caller-provided child-process connection to an
empty loopback DB named `tct_acceptance_writing_*` on3308–3399; it refuses dev or
nonempty databases before DDL. It migrates the disposable DB, applies only the36
selected canonical packages, compares persisted content/answers and repeats
with zero changed rows. Keep the connection in process environment, never argv.

For intermediate/advanced, first run `-Action baseline -Level <level>`. This
creates an additional ignored `<level>-before.json` without replacing the original
baseline. Later verification checks both snapshots, including earlier batch rows
and immutable package versions. Duplicate checks include earlier-level rows,
not just the original catalog. Use the remaining commands above with that level.
The initial baseline command with the same level is create-once on reruns.

Do not change `data/shared/production.json`, published package bytes, private
content, progress or earned rewards. Git/release steps need separate authority.
